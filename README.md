# Аудит безопасности WebLarek

Проектная работа: аудит интернет-магазина WebLarek на React, Express и MongoDB.

Автор: Александр Смирнов.

Репозиторий:

https://github.com/smirnov-dev-frontend/bad-server

## Запуск в Docker

Требуются Docker с Compose и свободные порты 80, 3000 и 27018.

```bash
docker compose up --build -d
```

Импортируйте демонстрационные данные по инструкции в [.dump/README.md](.dump/README.md).

Магазин: http://localhost/, вход: http://localhost/login/, админ-панель: http://localhost/admin/.

## Исправленные уязвимости

| Проверка       | Реализация                                                                                                                                                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| XSS            | Текстовые поля очищаются перед сохранением. HTML комментариев проходит `sanitize-html` на сервере и DOMPurify перед отображением и передачей редактору. Разрешены только форматирование и HTTP(S)-ссылки.                                          |
| CSRF           | `GET /auth/csrf-token` выдаёт токен и подписанную HttpOnly cookie `_csrf`. Все изменяющие запросы требуют `X-CSRF-Token`, связанный с cookie. Выход и обновление сессии используют POST.                                                           |
| NoSQL-инъекции | Joi проверяет типы, разрешённые поля, идентификаторы и параметры поиска. Произвольные операторы MongoDB и поля ролей отклоняются; сервер формирует фильтры самостоятельно.                                                                         |
| Размеры данных | JSON и формы ограничены 32 КБ, корзина — 100 уникальными товарами. Ограничены строки, номера страниц и число записей: до 10 покупателей/заказов или 100 товаров.                                                                                   |
| ReDoS          | Поиск экранируется через `escapeRegExp`; длина запроса ограничена 100 символами. Проверка телефона использует выражение без вложенных повторений, длина ограничена 26 символами.                                                                   |
| Перегрузка     | Сервер ограничивает IP до 120 запросов в минуту и 30 в секунду, вход — до 20 попыток в минуту. Добавлены тайм-ауты, лимиты nginx и кэширование статики. Логи Docker ротируются, запросы и ошибки атак не записываются приложением в лог.           |
| Path Traversal | Статика ограничена каталогом изображений. Пути изображений проверяются, перемещение и удаление учитывают фактический путь файла. Временные загрузки находятся вне публичного каталога.                                                             |
| Файлы          | Допускаются изображения размером от 2 КБ до 5 МБ и до 4 млн пикселей. Sharp проверяет содержимое и пересохраняет его в PNG с новым UUID-именем. SVG и неподдерживаемые форматы отклоняются; одновременно обрабатываются не более двух изображений. |
| Учётные записи | MD5 заменён на bcrypt с cost 12. Refresh-токены проверяются по сохранённому HMAC и отзываются атомарно; повторное использование отклоняется. Проверки ролей защищают административные операции.                                                    |

Неиспользованные временные загрузки удаляются через час; очистка выполняется при запуске и каждые 10 минут. При замене или удалении товара изображение удаляется, если другие товары его не используют.

Срок access-токена по умолчанию — 10 минут, refresh-токена — 7 дней. Без заданных секретов в режиме разработки сервер генерирует случайные значения при запуске, поэтому перезапуск завершает существующие сессии. Для production задайте `NODE_ENV=production`, HTTPS и три независимых случайных секрета длиной не менее 32 байт: `AUTH_ACCESS_TOKEN_SECRET`, `AUTH_REFRESH_TOKEN_SECRET`, `CSRF_SECRET`. Cookie получают `Secure` в production. `ORIGIN_ALLOW` содержит разрешённые адреса клиента через запятую. `TRUST_PROXY=true` включается только за доверенным прокси при закрытом прямом доступе к API.

Лимиты в памяти рассчитаны на один экземпляр сервера. Для нескольких экземпляров нужен общий счётчик запросов; защита от сетевых DDoS требует ограничений на уровне инфраструктуры.

## Проверки

Для локальных проверок требуется Node.js 22.12 или новее.

```bash
npm ci --prefix backend
npm ci --prefix frontend
npm run build --prefix backend
npm run lint --prefix backend
npm test --prefix backend
npm audit --prefix backend
npm run build --prefix frontend
npm run lint --prefix frontend
npm audit --prefix frontend
```
